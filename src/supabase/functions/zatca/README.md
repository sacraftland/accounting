# الربط مع هيئة الزكاة (المرحلة الثانية) — `functions/zatca`

## الجزء 1 (جاهز): الملف والتوقيع — `core.js`
- `buildInvoiceXML` يبني الفاتورة بصيغة UBL 2.1: ضريبية (388 / 0100000)، مبسطة (388 / 0200000)، إشعار دائن (381) ومدين (383) مع مرجع الفاتورة والسبب.
- `invoiceHash` تجزئة الفاتورة مثل أداة الهيئة (حذف التوقيع والـQR ثم الصيغة القانونية C14N).
- `signInvoice` توقيع ECDSA على المنحنى secp256k1 بصيغة XAdES، وQR المرحلة الثانية (الوسوم 1–9).
- `buildCSR` طلب الشهادة بالحقول التي تشترطها الهيئة (قالب الشهادة، الرقم التسلسلي للجهاز، الرقم الضريبي، أنواع الفواتير، العنوان، النشاط).
- بدون أي مكتبات خارجية: يعمل في Supabase Edge Functions (Deno) وفي Node.

الاختبار:
```
openssl ecparam -name secp256k1 -genkey -noout -out key.pem
openssl req -new -x509 -key key.pem -out cert.pem -days 365 -subj "/CN=test"
node tests/zatca_core_test.mjs <dir> cert.pem key.pem      # يبني ويوقّع، ويطابق عينة الهيئة الرسمية
python3 tests/zatca_check.py <dir> cert.pem                 # تحقق مستقل: C14N بـ lxml، التوقيع بـ cryptography، الإجماليات، الطلب
```

## الجزء 2 (التالي): بيئة الاختبار
خدمة Edge Function تحفظ المفتاح الخاص في Supabase Vault (لا يصل للمتصفح أبداً)، تطلب شهادة الامتثال (Compliance CSID)،
وترسل الفواتير التجريبية المطلوبة (ضريبية، مبسطة، دائن، مدين) لفحص الامتثال.

## الجزء 3 (بعد الرقم الضريبي): الإنتاج
رمز OTP من منصة فاتورة ← شهادة الإنتاج ← اعتماد فوري للفواتير الضريبية (Clearance) وإبلاغ عن المبسطة خلال 24 ساعة (Reporting).
