# ١. التثبيت من الصفر

تسع خطوات بالترتيب. كل خطوة فيها «كيف تتأكد» — لا تنتقل للي بعدها قبل ما تتأكد.

---

## الخطوة 1 — مشروع Supabase جديد

1. ادخل [supabase.com](https://supabase.com) وسجّل دخولك ← **New project**.
2. **Name:** اسم واضح، مثل `craftland` أو اسم العميل.
3. **Database Password:** كلمة مرور قوية — **احفظها عندك** (ما تحتاجها للبرنامج، لكن تحتاجها لو أردت الدخول المباشر لقاعدة البيانات).
4. **Region:** أقرب منطقة متاحة (مثل Frankfurt أو Mumbai أو Bahrain إن وُجدت).
5. اضغط **Create new project** وانتظر دقيقتين حتى يجهز.

✅ **كيف تتأكد:** تظهر لوحة المشروع بدون رسالة «Setting up project».

## الخطوة 2 — إنشاء قاعدة البيانات

1. من القائمة الجانبية: **SQL Editor** ← **New query**.
2. افتح الملف `database/setup.sql` بأي محرر نصوص (Notepad أو VS Code)، انسخ **كل** محتواه، والصقه في المحرر.
3. اضغط **Run** (أو Ctrl+Enter).
4. إذا ظهر تحذير «destructive operation» فهو بسبب أوامر الإنشاء — اضغط **Run this query**.

✅ **كيف تتأكد:** تظهر `Success. No rows returned`.

> شغّله **مرة واحدة فقط** على مشروع جديد. لو ظهر خطأ «already exists» فالمشروع مو جديد — انظر `6-حل-المشاكل.md`.

## الخطوة 3 — تحديد مالك النظام

النظام **بالدعوة فقط**: ما أحد يقدر يسجّل إلا المالك، والمالك يدعو الباقين.

1. افتح `database/owner.sql`، غيّر `owner@example.com` إلى **بريدك أنت** (اللي بتسجّل فيه).
2. الصقه في **SQL Editor** ← **New query** ← **Run**.

✅ **كيف تتأكد:** `Success. 1 row`.

> تقدر تضيف أكثر من مالك بتكرار السطر ببريد ثاني.

## الخطوة 4 — فحص التثبيت

1. الصق محتوى `database/check.sql` في **New query** ← **Run**.

✅ **كيف تتأكد:** كل الأسطر في النتيجة فيها ✓، وآخر سطر «التثبيت سليم — مستوى قاعدة البيانات 18».

## الخطوة 5 — إعدادات الدخول والبريد

### 5-أ عنوان الموقع
**Authentication ← URL Configuration**
- **Site URL:** رابط موقعك النهائي (من الخطوة 6)، مثل `https://اسمك.github.io/accounting/`
- **Redirect URLs** ← **Add URL:** نفس الرابط.

> إذا ما تعرف الرابط الآن، ارجع لها بعد الخطوة 6. بدونها روابط التأكيد ترجع لعنوان خاطئ.

### 5-ب تأكيد البريد
**Authentication ← Sign In / Providers ← Email:** مفعّل، و **Confirm email** مفعّل.

### 5-ج ربط بريد Gmail (ضروري قبل دعوة موظفين)
البريد المدمج في Supabase للتجربة فقط ويرسل رسائل قليلة جداً في الساعة.

1. في حساب Google: **Manage your Google Account ← Security ← 2-Step Verification** (فعّلها إن لم تكن مفعّلة) ← **App passwords** ← أنشئ كلمة مرور تطبيق باسم `Supabase` ← انسخ الـ16 حرفاً.
2. في Supabase: **Authentication ← Emails ← SMTP Settings** ← **Enable custom SMTP**:

| الحقل | القيمة |
|---|---|
| Sender email | بريد Gmail نفسه |
| Sender name | اسم الشركة، مثل `كرافت لاند` |
| Host | `smtp.gmail.com` |
| Port | `465` |
| Username | بريد Gmail نفسه |
| Password | كلمة مرور التطبيق (الـ16 حرفاً) |

3. **Save**.

✅ **كيف تتأكد:** بعد الخطوة 8، تصلك رسالة التأكيد من بريدك خلال دقيقة.

### 5-د (اختياري) قوالب الرسائل بالعربي
**Authentication ← Emails ← Templates:** ترجم «Confirm signup» و «Reset password» و «Magic Link».

## الخطوة 6 — رفع البرنامج (GitHub Pages)

1. في [github.com](https://github.com): **New repository** ← الاسم مثل `accounting` ← **Public** ← **Create repository**.
   > مستودع عام آمن: المفتاح الموجود في البرنامج عام بطبيعته، والحماية كلها داخل قاعدة البيانات.
2. **Add file ← Upload files** ← ارفع `app/index.html` و `app/privacy.html` ← **Commit changes**.
3. **Settings ← Pages** ← Source: **Deploy from a branch** ← Branch: `main` و `/ (root)` ← **Save**.
4. بعد دقيقة يظهر الرابط أعلى الصفحة: `https://اسمك.github.io/accounting/`.

✅ **كيف تتأكد:** الرابط يفتح البرنامج ويظهر شريط «تجريبي — على هذا الجهاز» (لأنه لسا ما ارتبط بقاعدة البيانات).

> بديل: أي استضافة ملفات ثابتة تدعم **HTTPS** (Netlify، Cloudflare Pages، استضافتك الخاصة). البرنامج ملف واحد فقط.

## الخطوة 7 — ربط البرنامج بقاعدة البيانات

1. في Supabase: **Project Settings ← API Keys** (أو **Data API**) انسخ:
   - **Project URL** — مثل `https://abcdxyz.supabase.co`
   - **Publishable key** (أو `anon` key) — يبدأ بـ `sb_publishable_` أو `eyJ`
   - ⚠️ **لا تنسخ** `service_role` ولا `secret` أبداً.
2. في GitHub افتح `index.html` في مستودعك ← أيقونة القلم ✏️ (Edit) ← ابحث (Ctrl+F) عن `SUPABASE_CONFIG` في أول الملف، وضع القيمتين:
   ```js
   const SUPABASE_CONFIG = {
     url: 'https://abcdxyz.supabase.co',
     anonKey: 'sb_publishable_xxxxxxxx',
   };
   ```
3. **Commit changes** وانتظر دقيقة.

✅ **كيف تتأكد:** افتح الرابط من نافذة خاصة (Incognito) — تظهر شاشة تسجيل الدخول، وما يظهر شريط «تجريبي».

> طريقة سريعة للتجربة بدون تعديل الملف: من داخل البرنامج **الإعدادات ← الاتصال بالخادم** والصق العنوان والمفتاح. لكنها تنحفظ في هذا المتصفح فقط — للتشغيل الفعلي عدّل الملف.

## الخطوة 8 — أول دخول وإنشاء الشركة

1. افتح البرنامج ← **إنشاء حساب** بالبريد اللي حطيته في الخطوة 3 ← كلمة مرور.
2. افتح رسالة التأكيد في بريدك واضغط الرابط.
3. ادخل ← تظهر شاشة **إنشاء الشركة**: الاسم، الرقم الضريبي (15 رقم يبدأ وينتهي بـ 3)، المدينة.

✅ **كيف تتأكد:** تفتح لوحة التحكم باسم الشركة، وفي «شجرة الحسابات» تظهر الحسابات السعودية الجاهزة.

## الخطوة 9 — (اختياري) استرجاع بيانات من نسخة احتياطية

لو عندك ملف نسخة احتياطية (`craftland-….json.gz`) من نظام سابق:
**الإعدادات ← النسخ الاحتياطي ← استرجاع نسخة** ← اختر الملف ← **كشركة جديدة**. التفاصيل في `5-النسخ-والاسترجاع.md`.

## (اختياري) الدخول بحساب Google

1. [console.cloud.google.com](https://console.cloud.google.com) ← مشروع جديد.
2. **Google Auth Platform ← Branding** (أو OAuth consent screen): النوع **External**، اسم التطبيق، بريد الدعم ← حفظ. الصلاحيات: `email` و `profile` و `openid` فقط.
3. **Clients ← Create client** ← النوع **Web application**:
   - **Authorized JavaScript origins:** `https://اسمك.github.io` (النطاق فقط بدون مسار)
   - **Authorized redirect URIs:** الرابط اللي تعرضه Supabase في صفحة Google provider، بالشكل `https://abcdxyz.supabase.co/auth/v1/callback`
4. انسخ **Client ID** و **Client secret** ← Supabase **Authentication ← Sign In / Providers ← Google** ← فعّله والصقهما ← Save.
5. في Google: **Audience ← Publish app** عندما تجهز (في وضع Testing ما يدخل إلا المضافين كمختبرين).

## (اختياري) نطاق خاص

في GitHub: **Settings ← Pages ← Custom domain** ← اكتب النطاق، وأضف عند مزوّد النطاق سجل `CNAME` يشير إلى `اسمك.github.io`. بعدها حدّث **Site URL** و **Redirect URLs** في الخطوة 5-أ وروابط Google بالنطاق الجديد.
