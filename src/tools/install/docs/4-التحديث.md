# ٤. تحديث نسخة مثبّتة لآخر إصدار

التحديث له جزءان: **قاعدة البيانات** ثم **البرنامج**. بهذا الترتيب دائماً.

> ⚠️ قبل أي تحديث: **نزّل نسخة احتياطية** من البرنامج (الإعدادات ← النسخ الاحتياطي ← تنزيل نسخة كاملة).
> ⚠️ لا تشغّل `setup.sql` على نسخة فيها بيانات — هو للتثبيت الجديد فقط.

## 1. اعرف مستوى قاعدة بياناتك

في Supabase: **SQL Editor** ← الصق `database/check.sql` ← **Run**.
آخر سطر يقول «مستوى قاعدة البيانات N». مستوى هذا الإصدار مكتوب في `VERSION.txt`.

## 2. شغّل التحديثات الناقصة بالترتيب

من `database/migrations/` شغّل كل ملف رقمه **أكبر** من مستواك، واحداً واحداً بالترتيب:

| مستواك | شغّل |
|---|---|
| 12 | `13_…` ثم `14_…` ثم `15_…` ثم `16_…` |
| 13 | `14_…` ثم `15_…` ثم `16_…` |
| 14 | `15_…` ثم `16_…` |
| 15 | `16_…` |
| 16 | لا شيء — قاعدة البيانات محدّثة |

لكل ملف: **New query** ← الصق المحتوى ← **Run** ← تأكد من `Success` قبل الملف التالي.
بعد آخر ملف شغّل `check.sql` مرة ثانية — يجب أن يظهر المستوى الجديد.

> لو فشل ملف في المنتصف، ما يتغير شيء (كل ملف يُنفّذ كوحدة واحدة). صوّر رسالة الخطأ وراجع `6-حل-المشاكل.md`.

## 3. حدّث البرنامج

1. في مستودع GitHub افتح `index.html` الحالي وانسخ القيمتين في `SUPABASE_CONFIG` (العنوان والمفتاح).
2. ارفع `app/index.html` الجديد مكان القديم (**Add file ← Upload files** يستبدل الملف).
3. افتح الملف الجديد ← ✏️ Edit ← ضع القيمتين في `SUPABASE_CONFIG` من جديد ← **Commit**.
4. انتظر دقيقة، ثم افتح البرنامج مع `?v=1` في آخر الرابط لتجاوز النسخة المخزّنة في المتصفح.

> للمطوّر: بدل الخطوات 1–3، ابنِ الملف بمفاتيحك مباشرة:
> `python3 source/app/build.py https://xxxx.supabase.co sb_publishable_xxxx` ثم ارفع `source/app/index.html`.

## 4. تأكد

- تسجيل الدخول يعمل، والأرقام في لوحة التحكم كما كانت.
- الصفحات الجديدة في هذا الإصدار تظهر في القائمة.
- نزّل نسخة احتياطية جديدة بعد التحديث.
