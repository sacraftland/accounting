# ٦. حل المشاكل

| المشكلة | السبب والحل |
|---|---|
| `setup.sql`: خطأ «already exists» | المشروع فيه جداول من قبل. استخدم مشروع Supabase جديد، أو للتحديث اتبع `4-التحديث.md` |
| `setup.sql`: «statement timeout» | شغّله مرة ثانية على مشروع جديد. لو تكرر، شغّل `migrations/` واحداً واحداً بالترتيب |
| `check.sql`: سطر فيه ✗ | الملف المذكور ما اكتمل — شغّل `setup.sql` على مشروع جديد |
| «هذا البريد غير مدعو» عند إنشاء الحساب | البريد مو في `owner.sql` (للمالك) أو ما وصلته دعوة (للموظف). تأكد أن البريد مكتوب بحروف صغيرة |
| البرنامج يفتح بشريط «تجريبي — على هذا الجهاز» | ما ارتبط بقاعدة البيانات: قيم `SUPABASE_CONFIG` فارغة أو غلط (الخطوة 7) |
| «تعذّر الوصول للخادم» | العنوان في `SUPABASE_CONFIG` غلط، أو مشروع Supabase متوقف (المشاريع المجانية تتوقف بعد أسبوع بدون استخدام — شغّله من لوحة Supabase بـ Restore) |
| رابط التأكيد يفتح صفحة خاطئة أو localhost | **Site URL** و **Redirect URLs** (الخطوة 5-أ) |
| ما تصل رسائل البريد | ربط Gmail (الخطوة 5-ج). تأكد أنك استخدمت «كلمة مرور تطبيق» وليس كلمة مرور Gmail العادية، وراجع مجلد Spam |
| «محاولات كثيرة» عند الدخول | حماية Supabase من التخمين — انتظر دقيقة |
| «الدخول بـ Google غير مفعّل» | فعّل Google في Supabase (قسم Google في `1-التثبيت.md`) |
| `redirect_uri_mismatch` من Google | رابط callback في Google Cloud يجب أن يطابق حرفياً ما تعرضه Supabase |
| Google: «This app is blocked» أو ما يدخل إلا أنا | التطبيق في وضع Testing — **Publish app** |
| التحديث رفعته لكن الشاشات القديمة تظهر | المتصفح يحفظ نسخة: افتح الرابط مع `?v=2` في آخره، أو Ctrl+Shift+R |
| الاسترجاع: «ملف النسخة غير صالح أو معدّل» | الملف تالف أو عُدّل يدوياً أو مو من كرافت لاند. جرّب نسخة أخرى |
| الاسترجاع: «هذه النسخة استُرجعت من قبل» | أعد اختيار الملف من جديد (يُجهَّز بأرقام جديدة كل مرة) |
| برنامج النسخ: «فشل تسجيل الدخول» | كلمة مرور حساب النسخ تغيّرت — شغّل `setup` من جديد |
| برنامج النسخ: «not allowed» | حساب النسخ ما عنده دور «النسخ الاحتياطي» في هذه الشركة |
| برنامج النسخ ما يشتغل والجهاز مقفل | نفّذ مرة واحدة: `sudo loginctl enable-linger $USER` |
